# Google Keynote 2.5D 商业动效设计法则（Omni 2.0）

本文件是 MGEasy 的视觉、动效与美术指导层，专为 **Google Flow / Gemini Omni** 优化：锁定 **Google Brand Studio / Material 3 商业发布会动效**的高级审美与干脆节奏，同时杜绝写实跑偏与廉价剪贴画感。

## 1. 视觉定位：Google Keynote 2.5D 混合商业动效

既不是死板的 2D 免费图标 PPT，也不是写实 3D 实拍广告，而是 Google I/O、Workspace、Gemini 发布会短片标志性的 **2.5D 混合商业动效**：

- **画布底色**：通透、干净、无实景的抽象商业色场（亮白/暖象牙/柔灰/莫兰迪浅色为主基调，章节高潮切换为深钴靛蓝、饱和品牌色或深炭墨色），常配 1 块流畅的大弧形/斜切辅助色面制造海报级构图张力。
- **材质轮换法则（防磨砂视觉疲劳）**：磨砂玻璃只是点睛材质，**绝不每镜必用**（建议相邻不超过 2–3 镜使用磨砂），全片应在以下 4 种 Google Keynote 轻材质间主动轮换：
  1. **纯平哑光矢量色块与大色面切割**（最利落、信息冲击力最强）；
  2. **不透明 Material 3 实心圆角卡片**（干净纯色底 + 柔和悬浮投影，现代感极强且零磨砂浑浊感）；
  3. **克制的磨砂玻璃 UI 卡片**（极细半透明亮边 + 柔和悬浮微阴影，留给关键界面/叠加对比镜点睛）；
  4. **精良 2D 现代商业插画**（用于 `story` 人物剧情或具象插画镜）。
- **文字默认纯平无体积感**：除非用户明确要求立体字或特殊材质字，画面文字一律默认使用 **纯平 2D 锐利粗体几何无衬线字（`flat 2D crisp bold geometric sans-serif`, zero 3D extrusion or volume）**，不写 `sculptural`、`extruded` 等诱发厚度的词——既更像顶级平面动效，又能显著提升中文字形稳定度。
- **绝不越界的去写实红线**：
  - **零实景环境**：绝不出现真实桌面、房间、电脑外壳、服务器机房、城市街景或真实人手；
  - **零物理质感与光学虚化**：不写 `lens`、景深虚化、纸张纤维、厚重金属反光或电影光晕；
  - **抽象骨架 UI（Graphic UI）**：UI 卡片内部只放简洁色块、抽象内容横条、圆角图形和彩色角标，绝不出现真实密集软件菜单或假小字。

## 2. 设计顺序与节奏错开法则（逐镜口述，不输出表格）

```text
选定表达方式（直接信息 / 视觉化展示 / 剧情推动，并与上一镜错开）→ 信息关系 → 1 个核心主体 + 2–3 个定制图形/UI 对象
→ 连续形变/剧情动作 → AE 2.5D 运镜与快起脆落节奏 → 画布色调与非对称海报构图 → 跨镜衔接 → 精简 Prompt
```

- **看全片节奏选型，拒绝“文字 PPT 化”**：三类表达方式是导演调色盘，结合当前句意图与上一镜类型主动换口味；避免连续超过 2 镜都做纯文字的“直接信息”，能用“视觉化展示”或“剧情推动”拉出变化时主动切换（剧情推动统一用精良 2D 商业插画人物 + 磨砂 UI，**绝不用真人实拍**）。
- **告别“廉价图标”与“卡片乱码小字”**：不要把主体写成 `icons`（易触发廉价剪贴画），一律具象为定制平面/UI 商业模块；磨砂玻璃卡片内部明确写清“抽象色条与简洁圆点、零内部小字”，防止模型在按钮或卡片里乱画模糊英文小字。
- **单一核心信息与连续形变**：每个 Shot 只讲 1 个核心信息、选 1 个主运动任务（`reveal / focus / transform / connect / compare / sequence / assemble / resolve`），让**同一对象从起点形态脆爽变形到终点形态**，不做一堆孤立元素的轮流站队。
- **非对称海报级构图**：善用大色面分割、悬殊字号尺度差（巨型主标题/主数字配精炼副标）和干净留白，避免每镜都机械正居中。若后期需配字幕，主动留出底部清晰安全区。

## 3. AE 2.5D 动效运镜与快起脆落节奏

**运镜不等于写实**——Google 商业动效的爽感正来自极干脆的 **After Effects 2.5D 摄像机编排** 与 **快起脆落（Fast-Attack, Crisp-Settle）** 的关键帧速度曲线：

### 5 种标志性 AE 2.5D 动效运镜
1. **斜向 2.5D 图层穿推（Diagonal 2.5D Parallax Push）**：摄像机沿斜角 brisk 推进穿过悬浮的前中后三层图形与磨砂玻璃卡片，前景大物件高速擦边掠过，中景排版锐利稳进。
2. **指数级急推 / 疾拉（Snappy Exponential Zoom-In / Pull-Back）**：从顶满画面的巨型字母或卡片瞬间急拉展露全局，或急加速扎进核心主标/数值。
3. **画板甩镜横移（Crisp Whip-Pan Slide）**：摄像机在无限大抽象商业画板上高速横甩或纵甩，带干脆的减速刹停，利落切入新信息区块。
4. **锁定主体跟拍（Object-Locked Tracking Glide）**：摄像机紧咬正在变形、滑行的 UI 卡片或图形横穿画布，背景大色面随动势利落切分。
5. **干脆平面微倾（Dynamic 2.5D Bank & Tilt）**：镜头伴随动效曲线干净倾斜 10°–15° 再利落回正，赋予画面极强的商业片灵动张力。

### 快起脆落的节奏词库（替代慢吞吞描写）
- **优先使用**：`snappy pop-in`、`tight overshoot bounce`、`whip-fast exponential ease-out`、`punchy magnetic snap`、`brisk whip-pan`、`decisive zero-lag morph`、`crisp micro-overshoot settle`、`energetic commercial pacing`。
- **避免拖沓词**：少用 `slowly drifts`、`gently floats`、`gradually fades` 等让画面像慢速 PPT 的词汇。
- **粗时间分段**：`3–8s` 固定 **2 段**整数秒，`9–12s` 为 **2 或 3 段**整数秒，`13–15s` 为 **3 或 4 段**整数秒，连续覆盖 `0–Ns`，严禁小数秒。时间段描述同一条不中断的高能动势，不因分段而停顿或重置。

### 标题镜策略
标题镜必须是一个高张力连续动效镜头，绝非静态标题卡。向用户提供 2–3 种截然不同的动态开场供选（如：巨型主标极速拉远、大色面甩镜/遮罩利落揭开、前景磨砂玻璃卡片瞬间变形展开），背景优先选高辨识度的明亮通透商业底或饱满深色场。

## 4. 色彩与相邻镜头节奏

- **明亮通透优先，深浅交替**：Google 商业片通常以**亮白/暖象牙/柔浅灰/淡青/浅奶油黄**做主基调，配合 Google 标志性的高纯度点睛色（钴蓝、翠绿、暖黄、珊瑚朱红），在代码、Agent、模型或高潮转折章节切入**深钴靛蓝、深墨蓝或纯粹炭黑**制造视觉冲击。
- **相邻镜头必须换气**：避免连续多镜同一种底色或同一种运镜方向（例如上一镜向右斜推，下一镜可用极速拉远或向上甩镜）。
- **色名代替 Hex（且用高稳定度标准色，转场禁用品牌色名）**：在视频 Prompt 正文中直接用高稳定度标准色名（如 `pure white`、`cream-beige`、`vivid royal-blue`、`bright red`、`bright yellow`、`bright green`），少用文艺生僻色名以免抽卡色差过大；**严禁在转场纯色场上写 `Google-blue` / `Google green`**（会诱导 Omni 画出谷歌 Logo），统一写 `plain solid royal-blue field with zero logos`。
- **人物与材质细节**：出现 2D 商业插画人物时必须明确指定性别与核心穿搭；拉幕类转场一律写 `flat solid matte 2D graphic wipe panel`，禁用 `curtain`（防真实布褶）。

## 5. 跨镜衔接双模式

根据用户在第 4 步选定的制作模式设计首尾衔接：

1. **模式 A：首尾帧参考衔接（Omni / Flow 推荐）**
   - 上一镜生成满意后，截取最干净的一帧作为下一镜的 Start Frame 上传给 Omni。
   - **上一镜出口**：设计一个构图干净、动势指向明确的定格或过渡构图；
   - **下一镜 Prompt 写法**：明确从首帧出发，**不再重复描写首帧已有的静态外观与颜色**，专注描写首帧中的已有图形/卡片如何干脆变形、甩镜或缩放展开新内容（见 [omni-iteration.md](omni-iteration.md)）。
2. **模式 B：纯文生色场接力（无参考图独立并发生成）**
   - **非末镜出口**：在末段尾声通过**核心主体放大吞屏**或**从画外疾速扫入全高纯色遮罩**干脆收满全屏纯色场（**严禁在第 0 秒就在画边提前停一块纯色方块等转场**），使用不带品牌名的纯色名并注明 `zero logos`；
   - **下一镜入口**：直接从同一标准色名的全屏纯色场利落展开。
3. **末镜（含单镜成片）**：有上一镜时照常承接入口；结尾只完成本镜内容收束与干脆的弹性定格，不做全屏纯色出场转场。

## 6. 严格因果时序与一眼可辨结构（实战防翻车铁律）

- **开场段严禁剧透后半段元素**：Prompt 第 2 段（开场状态）**只能描写第 0 秒真正存在于画面的东西**；凡是在 `[0–Xs]` 或 `[X–Ys]` 才触发弹出的文字、卡片或遮罩，**绝不能提前写在开场段**，必须在对应时间段里写清触发先后顺序（例如“她先双手扶太阳穴，随后头顶才弹出文字”）。
- **拒绝“极简到看不出是啥”**：环状图写清白色分缝、柱状图写清水平基线轴与淡网格、表格写清表头行与纵横网格、视频卡写清播放三角与底部播放条——用清晰结构让观众 0.5 秒认出，同时保持卡片内部零杂乱小字。
- **同体连续变形必须锁死物理对象**：如字母 `O` 变环状图，写清其余字母滑出画外、**就是同一个 `O` 原地裂变**，避免镜头冲过原字后凭空冒出无关新图形。

## 6. 中文排版与信息保真

- **空间绑定优先于清单罗列**：直接在画面描写中把每一个获准字符串绑定到具体位置、大小层级和对应图形上，并用 `crisp, bold geometric sans-serif typography with high contrast` 锁死字体稳健度，避免细笔画粘连。
- **完整字形直接呈现**：严禁写成由其他图形拼凑或逐笔生成汉字；阅读时段让文字稳居清晰的中景平面，避免过度透视畸变或长时间遮挡。
- **短词预算与提前降级**：单行中文建议 ≤ 10–12 字，单镜 ≤ 3–4 个可见短语；容易写错的长句、复杂时间单位在设计阶段就降级交给口播或后期字幕。
- **数据与实体保真**：虚构数据保留“示例数据”标注，图形比例与数值严格一致，不复制重复数字；概念物体不编品牌名和参数规格。
